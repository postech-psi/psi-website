PSI’s current flight computer divides work between the two cores of the Arduino Portenta H7. Sensor processing and flight decisions stay on M7, while M4 handles SD logging and the XBee telemetry path. The separation keeps a durable onboard record alongside the data sent to the ground.

Sensor acquisition, vertical-state estimation, flight-state and recovery decisions.

M4
Logging & telemetry · configured 25 Hz transmission

Decimated XBee transmission with a separate SD-writer thread for storage.

Estimate the vertical motion

The unscented Kalman filter (UKF) combines global-Z acceleration from the IMU with barometric altitude, updating at approximately 50 Hz when fresh barometric samples arrive. GNSS supports position recording and recovery; it is not an input to this vertical-state UKF or the flight-state decision path.

The rates above describe the configured software cadence, not a measured end-to-end performance guarantee.

An integrated ground station

The current Python interface brings 3D attitude, position history and flight measurements into one dashboard. Available plots cover acceleration, angular rate, altitude, vertical velocity and predicted apogee; acceleration and altitude are the default visible plots. A grid or offline map provides context for the recorded positions.

Flight statistics, sensor freshness, telemetry and system logs sit alongside recorded-log playback. Opening a log, pausing, seeking and replaying at 1–50× speed support post-test inspection. A sensor-health indicator describes incoming data freshness, not a guarantee of a GNSS fix or flight readiness.

Ground testing / public source

Thrust Measurement
System

From a force
to a useful record.

Explore the TMS repository

The Thrust Measurement System (TMS) connects instrumented ground testing to calibration, logs and analysis. Its value is the traceable route from a sensor signal to a measurement that can be inspected.

Acquisition and storage

An Arduino Nano reads load-cell and pressure signals through two ADS1115 channels and stores measurements on an SD card. The acquisition code configures 320 samples per second; that is distinct from the ADC’s conversion-rate setting.

Calibration and interpretation

Python tools support calibration, filtering and thrust/impulse analysis. The public test archive keeps plots and experiment notes beside processed data, including instrument anomalies and other limitations.

Aircraft programme

More than
a rocket team.

The Aircraft Team designs and fabricates quadrotor and VTOL aircraft for competition activity.

The research archive also asks how vortex generators affect flight stability and how mesostructures relate to the behaviour of small aircraft. These historical studies and current programme descriptions are different parts of the same broader interest in flight.

The current precision-landing study combines a conventional controller with PPO-based residual corrections. It is a simulation feasibility study, with real-flight validation still ahead.
